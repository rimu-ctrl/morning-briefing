커서 ‘Automations’으로 프로젝트 개선한 후기

#커서#‘Automations’으로#프로젝트#개선한

AI와 코딩하면 속도는 빨라집니다. 대신 다른 부담이 생겼습니다. PR이 늘고, 에이전트가 만든 코드를 사람이 다시 리뷰하는 시간이 늘었습니다. 그리고 릴리즈 노트, 버전업, 중복 정리 같은 반복 유지보수는 점점 뒤로 밀리게 됩니다. 한동안 저는 이걸 ‘skills’를 만들어서 틈틈이 정리해 왔습니다. 그런데 이것을 챙기는 것도 꽤 버거운 일이더군요. 그래서 커서의 Automations 기능을 활용하여, 구체적이고 자동화된 시스템을 만들었습니다. 프로젝트를 반복적으로 개선하는 저만의 워크플로우를 만든 거죠. 이번 글에서는 이 경험을 나누고자 합니다.

🇰🇷 핵심 요약

  • AI와 코딩의 결합으로 작업 속도가 빨라지지만, PR 증가로 인한 코드 리뷰 시간이 늘어나는 부작용이 있습니다.
  • 반복적인 유지보수 작업인 릴리즈 노트와 버전 관리를 소홀히 하게 되어 전체 효율성이 저하될 수 있습니다.

가재와 고블린은 왜 AI 프론티어의 상징이 됐을까

OpenAI는 공식 글로 ‘고블린’ 표현의 유래를 설명하고, OpenClaw 커뮤니티에서는 에이전트를 돌보는 일을 ‘가재 키우기’라 부르죠. 그러나 사실은 AI 업계가 밈과 캐릭터에 빠진 게 아니라, 밈이 가장 빠르게 퍼질 수 있는 구조를 가진 업계가 AI 업계였던 겁니다. 기술은 회사가 만들지만, 문화는 사용자들이 키웁니다. 밈이 사람을 구경꾼에서 참여자로 바꿔 커뮤니티를 키우고, 퍼질수록 더 강한 락인을 만드는 해자가 되는 과정을 짚었습니다.

🇰🇷 핵심 요약

  • OpenAI의 ‘고블린’ 설명과 OpenClaw 커뮤니티의 ‘가재 키우기’ 같은 사례는 사용자 참여의 중요성을 강조합니다.

  • 밈은 사용자들이 에이전트와 상호작용하도록 유도하며, 이를 통해 커뮤니티의 결속력과 참여도를 높이는 효과를 가져옵니다.

클로드 채널, 이렇게까지 쓸 수 있다

#클로드#채널#이렇게까지#있다

클로드 코드 자동화를 헤드리스 모드에서 채널 기반 세션으로 옮긴 이야기입니다. MCP가 필요할 때 당겨오는 풀(Pull) 구조라면, 채널은 외부 이벤트를 클로드 세션에 밀어 넣는 푸시(Push) 구조인데요. 살아 있는 라이브 클로드 세션을 PTY로 띄워 자동화 런타임으로 쓰고, 컨트롤러를 라우터 삼아 클로드와 코덱스를 대화시키는 구현까지. 정책 변경은 하루 만에 철회됐지만, 리서치 프리뷰 기능인 Claude Channel을 실무자가 실제 자동화에 어디까지 활용했는지 보여주는 사례로 클코나잇 2 발표를 정리했습니다.

✓ 자동 저장됨 · 다른 기기에서도 동일하게 보여요

🇰🇷 핵심 요약

  • 클로드 채널은 코드 자동화를 헤드리스 모드에서 채널 기반 세션으로 이동하면서 사용자 옵션을 확대했습니다.
  • 새로운 푸시 구조는 외부 이벤트를 실시간으로 클로드 세션에 적용할 수 있도록 하여, 더 즉각적이고 유연한 반응을 가능하게 합니다.
  • 이 기술은 자동화 런타임을 개선하며, 클로드와 코덱스 간의 상호작용을 더 매끄럽게 만들어 업무 효율성을 높일 수 있습니다.
  • 정책 변경이 하루 만에 철회되었음에도 불구하고, 클로드 채널의 활용 사례는 실무자들에게 큰 시사점을 제공하여 향후 발전 방향을 제시합니다.
  • 이와 같은 혁신은 IT 업계에서의 자동화 트렌드를 더욱 가속화하고, 사용자 경험을 개선할 기회를 제공합니다.
